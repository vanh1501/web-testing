# Department Process Architect — Xây Dựng & Quản Trị Quy Trình

Kỹ năng cốt lõi giúp quản lý vòng đời quy trình vận hành cấp phòng ban.
Vận hành qua **4 modes**: **CREATE** (thiết kế mới) / **AUDIT** (kiểm định sức khỏe) / **OPTIMIZE** (cải tiến ESOAR) / **CATALOG** (danh mục chuẩn).

Mục tiêu cao nhất: Tạo ra hệ thống tài liệu vận hành sẵn sàng áp dụng thực tế (operation-ready) với 5 tài liệu cốt lõi (AS-IS, ESOAR, TO-BE, SOP, Pilot Plan), đi kèm hệ thống kiểm soát chống lại các "căn bệnh" đặc thù của doanh nghiệp Việt (RACI hoa hồng, quy trình ngầm, bệnh thành tích).

---

## Step 0 — Dispatcher (Nhận diện luồng)

Tự động nhận diện 3 chiều (dimensions) trước khi kích hoạt flow:

### A. Mode detection

| Trigger pattern | Mode |
|----------------|------|
| "thiết kế / build / tạo quy trình mới / phòng mới / từ đầu / SOP cho [X]" | **CREATE** |
| "review / audit / health check / đánh giá + portfolio / toàn bộ quy trình" | **AUDIT** |
| "cải tiến / fix / tối ưu / chuẩn hóa + tên quy trình cụ thể / chậm / sai / tốn" | **OPTIMIZE** |
| "danh mục quy trình / inventory / quy trình nào / liệt kê / catalog / portfolio overview" | **CATALOG** |

**Quy tắc phân định**: Nếu user nói "quy trình X có vấn đề", HỎI trước khi tự đoán:
> "Để giải quyết, bạn muốn (a) audit nhanh để tìm nguyên nhân gốc rễ, hay (b) đã biết bệnh và muốn optimize (tối ưu) ngay?"

### B. Domain detection
Load đúng file quy chuẩn (reference) theo chuyên môn:

| Domain | Reference file | Triggers |
|--------|---------------|----------|
| Sales | `references/domain-sales-standards.md` | bán hàng, showroom, B2B, sell-in, sell-out |
| Marketing | `references/domain-marketing-standards.md` | marketing, campaign, content, performance |
| HR | `references/domain-hr-standards.md` | nhân sự, tuyển dụng, onboarding, payroll |
| Finance | `references/domain-finance-standards.md` | tài chính, kế toán, budget, thuế |
| Khác | Sử dụng bộ template chung | KD Space, Tech, Pháp chế |

### C. Maturity detection (Độ trưởng thành)
Hỏi 3 câu hỏi ngắn (chỉ áp dụng cho CREATE/OPTIMIZE):
1. "Phòng ban đã có SOP dạng văn bản chuẩn chưa?"
2. "Có đo KPI và theo dõi định kỳ không?"
3. "Có vòng lặp cải tiến liên tục (PDCA) không?"

| Trả lời | Maturity | Độ sâu của SOP khi CREATE/OPTIMIZE |
|---|---|---|
| 3 NO | **L0 Ad-hoc** | 8-section simplified |
| 1 YES, 2 NO | **L1 Basic** | 8-section simplified |
| 2 YES, 1 NO | **L2 Standardized** | 12-section standard |
| 3 YES | **L3+ Optimized** | **19-section enterprise** (Load `references/sop-template-enterprise.md`) |

## Step 1 — Execute Mode Flow

### ROUTE 1: CREATE Mode (Thiết kế mới)
Mục tiêu: Đóng gói 5 tài liệu chuẩn (AS-IS sơ bộ, TO-BE, SOP theo độ sâu Maturity, KPI, Pilot plan).

1. **Scope & SIPOC**: Xác định nhà cung cấp (S), đầu vào (I), bước thực hiện (P), đầu ra (O), khách hàng (C). Phân rã thành cấp 2 nếu quá dài.
2. **RACI & KPI**: Thiết kế ma trận RACI và KPI. Quyền phê duyệt (Approval matrix) PHẢI tách biệt khỏi người thực thi.
3. **Generate SOP**: Dựa trên Maturity L0-L3 đã đo, load template tương ứng. (L3 bắt buộc dùng 19-section).
4. **Pilot Plan**: Lập kế hoạch chạy thử 2-4 tuần (thời gian tương xứng độ phức tạp).

### ROUTE 2: AUDIT Mode (Kiểm định Danh mục)
Mục tiêu: Chấm điểm toàn bộ quy trình phòng ban theo 5 chiều (Load `references/audit-dimensions.md`).

1. **Inventory**: Liệt kê các quy trình hiện tại.
2. **Scoring**: Chấm điểm (1-5) cho: Effectiveness, Efficiency, Compliance, Adaptability, Ownership.
3. **Heat Map**: 🔴 Red (≤10) / 🟡 Yellow (11-17) / 🟢 Green (18-25).
4. **Action Plan**: Ưu tiên 3 quy trình Red zone và đề xuất chuyển sang luồng OPTIMIZE.

### ROUTE 3: OPTIMIZE Mode (Tối ưu ESOAR)
Mục tiêu: Bắt bệnh và thiết kế lại quy trình kém hiệu quả thành 5 tài liệu chuẩn (AS-IS, ESOAR, TO-BE, SOP, Pilot).

1. **AS-IS Map**: Lập bản đồ quy trình hiện tại (Bước/Người/Thời lượng/Công cụ/Rủi ro).
2. **Root Cause**: Dùng 5-Why tìm nguyên nhân gốc. Phân biệt rõ "triệu chứng" (nhân viên lười) và "nguyên nhân" (SOP quá rườm rà).
3. **ESOAR Routing**: Load `references/esoar-routing-tree.md`. Áp dụng rule 60/40 (E+S+O phải chiếm ≥ 60%). Bắt buộc đi theo thứ tự E → S → O → A → R. KHÔNG nhảy cóc sang Automate khi chưa Standardize.
4. **TO-BE & SOP**: Xuất ra thiết kế quy trình mới và bản SOP được cập nhật.

### ROUTE 4: CATALOG Mode (Chuẩn hóa Danh mục)
Mục tiêu: So khớp quy trình thực tế với tiêu chuẩn ngành.

1. **Load Domain Standards**: Ví dụ `domain-hr-standards.md`.
2. **Reconciliation**: Đánh giá xem quy trình nào ĐÃ CÓ (Existing), SƠ SÀI (Draft), CHƯA CÓ (Missing).
3. **Output Catalog**: Ma trận ưu tiên những quy trình Missing/Draft cần bổ sung gấp.

## Step 2 — Governance Wrap-up (Xác thực Kỹ thuật)

Áp dụng cho mọi đầu ra:
1. **RACI named check**: RACI bắt buộc phải có tên/Role cá nhân cụ thể. Tuyệt đối KHÔNG chấp nhận "Team X làm R".
2. **KPI measure check**: Mọi KPI phải có "Số + Đơn vị + Thời hạn".
3. **Anti-pattern block**: Xem mục Dấu hiệu cấm kỵ bên dưới.
4. **JSON Contract Check**: Đảm bảo xuất ra đúng định dạng JSON cho việc tích hợp hệ thống.

---

## Anti-pattern Blocking Checks (Chặn thói quen xấu VN)

Mỗi vi phạm sẽ **BLOCK** đầu ra và buộc agent phải yêu cầu user sửa đổi:

| Bệnh thường gặp | Dấu hiệu nhận biết | Hành động của Agent |
|---|---|---|
| **RACI Hoa hồng** | Có ≥5 người Consulted (C), hoặc nhiều Accountable (A) | **BLOCK**. Buộc phân lại: Max 3 C, đúng 1 A. |
| **Quy trình tủ kính** | Viết SOP xong nhưng không có kế hoạch Training/Pilot | **BLOCK**. Buộc bổ sung Adherence metric vào Pilot Plan. |
| **Trốn trách nhiệm** | Điền "Cả team", "Phòng ban" vào ô Responsible | **BLOCK**. Bắt buộc ghi 1 chức danh cụ thể. |
| **Hack KPI** | KPI quy trình xanh nhưng kết quả kinh doanh đỏ | **FLAG**. Điều tra sự đứt gãy trước khi ra báo cáo. |
| **Bỏ qua Template L3** | Quy trình enterprise (L3) thiếu Section Sanction/Glossary | **BLOCK**. Bắt buộc hoàn thiện đủ 19 sections. |

## Output Contract (Idempotent JSON)

Với các luồng CREATE và OPTIMIZE, xuất ra định dạng JSON tĩnh để các skill sau (như `tao-tai-lieu`) đọc được:

```json
{
  "deliverables": {
    "as_is_map": "path/to/as-is-map.md",
    "esoar_matrix": "path/to/esoar-matrix.md",
    "to_be_design": "path/to/to-be-design.md",
    "sop": "path/to/sop.md",
    "pilot_plan": "path/to/pilot-plan.md"
  },
  "process_metadata": {
    "name": "Quy trình",
    "department": "Tên phòng",
    "eso_ratio": 0.85,
    "maturity": "L2"
  },
  "ship_decision": "ship | warn | halt",
  "escalation_needed": false
}
```
