# Index Syncer

Skill bảo đảm single source of truth cho 12 tệp index của workspace. Đọc thực tế hệ thống tệp, đối chiếu với index, cập nhật entries có chênh lệch. Là tầng phòng vệ chống "bãi rác dashboard" — vấn đề phổ biến nhất trong workspace dùng 3+ tuần không có lớp đồng bộ tự động.

## When to use this skill

- Use when skill khác vừa sinh artifact mới trong `Du-An/{ten-du-an}/` hoặc `Kho-Du-Lieu/Ket-Qua/{...}/` — quy tắc 5 yêu cầu cập nhật index ngay
- Use when operator gõ `/cap-nhat-index` thủ công vì nghi ngờ dashboard lệch thực tế
- Use when workflow `/w-kiem-tra-suc-khoe` chạy audit định kỳ phát hiện entries thiếu/thừa
- Use when builder thêm/xóa skill, rule, workflow trong `.agents/` — index `DANH-SACH-KY-NANG.md` `DANH-SACH-QUY-TAC.md` `DANH-SACH-QUY-TRINH.md` cần cập nhật

**KHÔNG dùng skill này khi:**
- Workspace chưa cấu hình `Bang-Dieu-Khien/` (workspace mới chưa init) — chạy `/khoi-tao-workspace` trước
- Quá nhiều thay đổi đồng thời >50 tệp — đề xuất operator chạy `/w-kiem-tra-suc-khoe` để rebuild dashboard từ đầu, không sync incremental
- Operator đang trong giữa phiên làm việc dở (artifact tạm chưa final) — chờ cuối phiên mới sync

## How to use it

### Step 1: Quét thực tế hệ thống tệp

Đọc 4 thư mục nguồn dữ liệu cho 12 index:

| Index | Thư mục nguồn |
|-------|---------------|
| `BANG-DIEU-KHIEN.md` | Tổng hợp từ 6 danh sách domain |
| `DANH-SACH-DU-AN.md` | `Du-An/` (loại trừ `_archive/`) |
| `DANH-SACH-BAO-CAO.md` | `Kho-Du-Lieu/Ket-Qua/` |
| `DANH-SACH-DU-LIEU.md` | `Kho-Du-Lieu/Du-Lieu-Vao/` |
| `DANH-SACH-KY-NANG.md` | `.agents/skills/` (đọc frontmatter mỗi `SKILL.md`) |
| `DANH-SACH-QUY-TAC.md` | `.agents/quan-ly-quy-tac/` |
| `DANH-SACH-QUY-TRINH.md` | `.agents/workflows/` |

Quét → sinh in-memory snapshot thực tế hiện tại.

### Step 2: So sánh với index hiện có

Đọc 12 tệp index hiện có trong `Bang-Dieu-Khien/` (+ 3 tệp project trong mỗi `Du-An/{ten}/`).

Tính diff:

| Loại diff | Ý nghĩa | Hành động |
|-----------|---------|-----------|
| **Thiếu** | Tệp tồn tại trên disk, chưa có entry trong index | Thêm entry tự động |
| **Thừa** | Có entry trong index, tệp không tồn tại trên disk | Hỏi operator: xóa entry / restore tệp / archive? |
| **Sai metadata** | Entry tồn tại nhưng metadata lệch (ngày, đường dẫn, trạng thái) | Cập nhật metadata theo thực tế |

### Step 3: Áp dụng cập nhật

**Nhánh "thiếu":** Tự động thêm entry, không hỏi. Format theo schema trong `references/index-schema.md`. Cập nhật field "Cập nhật lần cuối" về thời điểm hiện tại.

**Nhánh "thừa":** Tuân thủ quy tắc 1 — không tự xóa. Hỏi operator:

```
Em phát hiện 3 entry trong DANH-SACH-BAO-CAO.md trỏ về tệp không
tồn tại trên disk:

1. bao-cao-q1-2026-03-15.md → file đã bị xóa
2. presentation-doi-thu.pptx → đường dẫn không đúng
3. evidence-pack-final.md → file đã đổi tên

Anh chọn xử lý:
(a) Xóa cả 3 entry khỏi index
(b) Restore tệp 1 từ git history (nếu có)
(c) Em archive entry vào LICH-SU-THAY-DOI.md, giữ lại lịch sử
(d) Anh review từng cái

Mặc định: (c) archive — không mất lịch sử.
```

**Nhánh "sai metadata":** Tự động sửa, ghi rõ trong commit log: "Sync metadata: {tệp} — {field cũ} → {field mới}".

### Step 4: Cập nhật BANG-DIEU-KHIEN.md tổng

Sau khi 6 danh sách domain đồng bộ xong → tổng hợp lại `BANG-DIEU-KHIEN.md` cấp master:

- Đếm số dự án đang chạy
- Tìm báo cáo gần nhất theo timestamp
- Đếm skill/rule/workflow có trạng thái "Hoạt động"
- Đánh giá sức khỏe workspace: Tốt / Cần kiểm tra / Có vấn đề

Tiêu chí sức khỏe:

| Trạng thái | Điều kiện |
|-----------|-----------|
| Tốt | 0 entry "thừa" + 0 báo cáo lỗi audit gần nhất |
| Cần kiểm tra | 1-3 entry "thừa" hoặc audit gần nhất phát hiện medium issue |
| Có vấn đề | >3 entry "thừa" hoặc audit phát hiện critical issue |

### Step 5: Validation cuối

- Ghi log `Quan-Tri/AGENT-LOG.md`: timestamp + số entry đã cập nhật + số entry hỏi operator
- Verify 12 index đều có field "Cập nhật lần cuối" mới
- Nếu có entry chờ operator quyết → return về orchestrator báo "đợi operator phản hồi", KHÔNG đánh dấu sync xong

## Decision tree

```
Phát hiện diff?
├─ Loại "thiếu" → Tự động thêm entry
├─ Loại "thừa" → Hỏi operator (4 lựa chọn)
└─ Loại "sai metadata" → Tự động sửa, ghi log
```

Multi-diff ở nhiều index cùng lúc:

```
Số diff trong batch hiện tại?
├─ <10 diff → Sync incremental (skill này xử lý)
├─ 10-50 diff → Sync incremental + cảnh báo trong báo cáo tuần
└─ >50 diff → STOP. Đề xuất operator chạy /w-kiem-tra-suc-khoe rebuild
```

## Edge cases & escalation

- **Tệp đổi tên giữa phiên:** Orchestrator sinh `bao-cao-draft.md`, operator đổi tên thành `bao-cao-cuoi.md` ở Finder. Index-syncer thấy diff "thừa entry cũ + thiếu entry mới". Đề xuất "(d) review từng cái" — operator xác nhận đây là rename, không phải xóa-tạo mới.
- **Conflict timestamp:** 2 skill ghi cùng 1 tệp trong 1 lượt — timestamp clash. Lấy timestamp ghi cuối làm chuẩn, log warning.
- **Permission lỗi:** Không đọc được thư mục nguồn (permission denied). Báo operator cụ thể đường dẫn lỗi, đề xuất kiểm tra quyền. KHÔNG silently skip.
- **Index file bị xóa thủ công:** Operator xóa `DANH-SACH-BAO-CAO.md` khỏi `Bang-Dieu-Khien/`. Skill phát hiện file thiếu → tái tạo từ template trong `kb-index-format.md` Phần 2.2 + populate entries hiện tại.
- **Loop trigger:** Skill này tự ghi `Bang-Dieu-Khien/` → quy tắc 5 trigger lại chính nó. Phòng chống: skip self-trigger, chỉ trigger khi nguồn thay đổi nằm ngoài `Bang-Dieu-Khien/`.

**Escalate** khi: 3 lần liên tiếp sync gặp diff >10 entry → ghi flag "high drift" trong báo cáo tuần, đề xuất audit quy trình ghi tệp của các skill khác.
