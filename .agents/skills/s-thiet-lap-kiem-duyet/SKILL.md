# Harness Engineer

Kiến trúc sư hệ thống (Harness Engineer) chịu trách nhiệm thiết lập các vòng lặp kiểm soát (hooks), bảo mật ngữ cảnh (scoped permissions), và cấu trúc xác minh chéo (maker-checker) nhằm gia tăng độ tin cậy và hạn chế ảo giác cho bất kỳ Agentic Workspace nào.

Bọc một lớp áo giáp chất lượng (Quality Control & Verification Layer) xung quanh MAS để biến quy trình chạy thuần túy thành hệ thống có Project Memory, Scoped Permissions và Maker-Checker theo đúng chuẩn **5-Zone Architecture, Zero-Floating Law và HPRF**.

## When to use this skill

- Workspace mới cần thiết lập Harness Layer (hooks, permissions, maker-checker).
- User nói "thiết kế harness", "thêm maker-checker", "cấu hình hooks", "experiment giam-sat-tuan-thu".
- `/optimize-workspace` cần harden workspace với verification layer.
- **KHÔNG dùng khi:** Audit chất lượng (dùng `qa` skill). Thiết kế architecture (dùng `architecture` skill).

## How to use it

1. Phase 1: Domain Intelligence Gathering (xác định domain, CRITICAL_GATE, compliance level).
2. Phase 2: Design 5-Layer Harness (Hooks → Permissions → Memory → Maker-Checker → Experiment).
3. Phase 3-5: Integration, Export, Scoring. Load templates từ `references/`.

## When to clarify

- Nếu SOW hoặc Brief không cung cấp mức độ Compliance Level (LOW/MEDIUM/HIGH), BẮT BUỘC hỏi User trước khi cấp Virtual Tokens.
- Xác nhận lại với User về `CRITICAL_GATE` nếu Domain có quá nhiều điểm rủi ro.

## Decision quan-ly-quy-tac

- If user mentions "thiết kế harness", "thêm maker-checker", "experiment giam-sat-tuan-thu" → **Route 1 (HARNESS DESIGN)**

## Process
Quy trình thiết kế gồm 5 Phase tuân thủ cấu trúc vật lý của hệ sinh thái MAS:

### Phase 1: Domain Intelligence Gathering

> [!WARNING] Bạn phải trích xuất Socratic OTC Check trước khi thao tác Tool

1. **CQS Size Gate (Pre-Check):** Any Harness Layer payload/brief < 0.5KB → Auto-FAIL (skeleton).
2. Xác định Domain Workspace (DA, BA, PM, Lecturer, v.v.).
3. Xác định `CRITICAL_GATE` (Bước rủi ro cao nhất cần Maker-Checker).
4. Đánh giá cấp độ bảo mật (Compliance Level: LOW/MEDIUM/HIGH).

### Phase 2: Harness Architecture Design

> [!WARNING] Bạn phải trích xuất Socratic OTC Check trước khi thao tác Tool

Thiết kế kiến trúc dựa trên 5 Layer. Bạn **BẮT BUỘC** gọi `view_file` tới các template trong thư mục `references/` trước khi sinh code:
- **L1 Hooks System:** (Xem `references/template-hooks-policy.yaml`)
- **L2 Scoped Permissions (Maker-Checker Virtual Tokens):** Bơm rào chắn xác thực Maker-Checker theo mô hình Zero-Trust. Bất kỳ Agent Worker nào muốn đẩy Output ra khỏi Sandbox (ghi đè file hệ thống) đều phải vượt qua một "Virtual Token Check" (thẻ thông hành ảo - giống cơ chế cấp quyền OAuth) do Harness (Checker) thiết lập và phê duyệt. (Xem `references/template-permissions.yaml`)
- **L3 Project Memory:** (Xem `references/template-memory-schema.yaml`)
- **L4 Maker-Checker:** (Xem `references/template-maker-checker.md`)
- **L5 Experiment Governance:** Track các thay đổi bằng metric.

### Phase 3: Integration & Wiring Verification

> [!WARNING] Bạn phải trích xuất Socratic OTC Check trước khi thao tác Tool

1. Đảm bảo mọi Agent SI trong workspace đích được cập nhật `[HARNESS INTEGRATION]`.
2. Xác nhận đường dẫn xuất file hoàn toàn chống rác Root (Zero-Floating Law).
3. Tích hợp `🚨 3-Strike Escalation Rule` vào Maker-Checker.

### Phase 4: Export & Scaffolding
Nếu có yêu cầu sinh file vật lý, gọi Python Script đính kèm tại `scripts/harness_scaffolder.py` hoặc xuất batching thủ công cho Workspace Designer.

### Phase 5: Quality Scoring
Đánh giá mức độ hoàn thiện của hệ thống: Hook specificity, permission granularity, Maker-Checker robustness.

## Output format
- File config dạng YAML/Markdown xuất trực tiếp vào `.agents/quan-ly-quy-tac/` và `artifacts/`.

## Quality checklist
- **Q-01:** File xuất ra có thả nổi ở Root không? (Chỉ chấp nhận vào `KB/`, `.agents/quan-ly-quy-tac/`, `.agents/memory_bus/`, `artifacts/`).
- **Q-02:** File config xuất ra có chứa khối `> [!IMPORTANT] Override Priority: Tier 2` không?
- **Q-03:** Cơ chế Maker-Checker có nhắc đến `3-Strike Escalation Rule` không?

## Guardrails

- `Float_Files_At_Root` → [DENY]. Configs must be placed in `.agents/quan-ly-quy-tac/`.
- `Missing_HPRF` → [DENY]. Always inject Override Priority Block.
- `Bypass_3_Strike` → [CIRCUIT BREAKER]. Max 2 rework loops (3 strikes). After strike 3 → HALT.
- `Skip_CQS_Gate` → [DENY]. Payload < 0.5KB = Auto-FAIL.
- `Repeated_Component_Failure > 3` → [CIRCUIT BREAKER]. HALT execution, escalate.

## Rules

- `Zero_Floating_Law` → [REQUIRE]. Configs must not use virtual dirs like `.agents/configs/`.
- `Mandatory_HPRF` → [REQUIRE]. Inject `> [!IMPORTANT] Override Priority: Tier 2`.
- `Immutable_3_Strike` → [REQUIRE]. Limit Checker rework to max 2 loops, then escalate.
